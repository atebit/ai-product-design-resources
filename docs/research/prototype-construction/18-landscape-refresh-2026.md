# Landscape Refresh, September 2026 — What Moved in "UI-as-Data", and What It Does to the Architecture's Bets

**Scope:** A re-verification pass over the prior art and load-bearing assumptions of the construction-file architecture ([00 synthesis](00-architecture-synthesis.md); catalog prior art in [01 §3](01-primitive-codification.md); structured-output and token-economics claims in [03 §2, §4, §5](03-construction-file-generation.md); codegen-vs-interpretation and skills packaging in [04 §1–3](04-deterministic-assembly.md); patch-iteration evidence in [05](05-surgical-editing-iteration.md)). It asks, as of 2 September 2026: what shipped in the "LLM emits UI-as-data, a deterministic renderer or builder realizes it" space, what is now table stakes, what is still open, and which of the architecture's bets are confirmed, weakened, or made redundant by products. It does **not** repeat the general prompt-to-UI tool landscape in [foundational/03](../foundational/03-ai-ui-generation.md) or the grading stack in [eval-tuning-loops/01](../eval-tuning-loops/01-grading-generated-prototypes.md). Every status claim carries a date.

## 2. Generative-UI protocols and SDKs

**The headline:** three open formats now do what doc 03 §4 described as a convergence in progress, and they converged on the *same shape as the construction file* — a flat, id-keyed map of catalog-constrained nodes, streamed incrementally. Two of the three then went one step further than the architecture did and added a compact non-JSON inference DSL. None of them ships an offline deterministic *builder*; all are runtime interpreters.

**Three observations that matter for the architecture.**

1. **Flat, id-keyed, catalog-constrained is now the industry default.** json-render's `elements` map, A2UI's "flat list … adjacency list", and OpenUI's `id = Component(...)` statements are the same data model the series chose (01 §1.4, 05 "id-keyed children"). A2UI states the reason verbatim: "a flat list of components with ID references which is easy for LLMs to generate incrementally." This bet is confirmed and commoditized simultaneously.
2. **The terse-DSL question doc 03 §1 closed has been reopened by shipping products.** OpenUI Lang claims "up to 67% fewer tokens than JSON"; A2UI Express targets "reducing output tokens by 55% to 70% compared to native A2UI wire payloads" for "on-device large language models" (Gemma 4 E2B/E4B), with a host-side compiler back to v1.0 JSON and an ANTLR grammar ([a2ui_express.md](https://github.com/a2ui-project/a2ui/blob/main/specification/proposals/express/a2ui_express.md), [Express.g4](https://github.com/a2ui-project/a2ui/blob/main/specification/inference_formats/express/Express.g4)). Both keep the DSL as an *inference* format and JSON as the *wire/validation* format — exactly the "enforced JSON wire + human-facing surface" split doc 03 recommended, but with the human surface swapped for a model surface. The only quality numbers are thesys's own benchmark (2026-08-17: OpenUI 96.9% vs A2UI 95.6% vs json-render 82.8% structural validity, 6,393 vs 15,433 vs 10,909 mean tokens, "46 prompts … 6 different models … same catalog of 70 components") — vendor-run and only partially disclosed, so treat as a hypothesis for E3, not a result.
3. **Nobody built the offline builder.** Every format above renders at runtime; json-render's `@json-render/codegen` is the closest thing to a codegen path and it is a toolkit ("Implement your own code generator"), not a product. The "spec → committed, diffable TSX" step remains unoccupied.

The verified rows agree on one thing: the design tools that have a catalog mode implement it as *retrieval + rules around code generation* (Figma's Code Connect lookup, Claude Design's validation against imported components), not as a schema-constrained data artifact. The Figma write path in particular is the opposite of a construction file — imperative JS in ≤10-operation chunks with screenshot validation — which is a strong argument that "Figma as the deterministic realizer" (03 §4.6) is not available: Figma exposes an *editor API*, not a *renderer of data*.

## 4. Structured outputs and the economics, recomputed

**Provider state (all verified 2026-09-02).**

| Provider | Status | Schema limits that bite a construction-file schema | Notes |
|---|---|---|---|
| Anthropic | Structured outputs **GA** — "beta headers are no longer required", `output_config.format`; supported on `claude-fable-5-1` … `claude-haiku-4-5-20251001` ([docs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)) | **"Recursive schemas" not supported**; `additionalProperties` must be `false`; no `minimum`/`maximum`/`minLength`; internal `$ref`/`$defs` OK; enums of primitives OK; PCRE2 `pattern` OK | "The first time you use a specific schema, there is additional latency while the grammar compiles"; "Compiled grammars are cached for 24 hours from last use"; changing the format "will invalidate any prompt cache for that conversation thread". Strict tools (`strict: true`) share the pipeline. On Fable 5.1 / Mythos 5.1, forced `tool_choice` `any`/`tool` returns 400 (release note 2026-09-01) — the "force one `emit_construction_file` tool" pattern from 03 §2.1 no longer works on the newest tier; use `output_config.format` or a strict tool with `auto`. |
| OpenAI | `strict` JSON Schema; recursion supported via `"$ref": "#"`; custom tools with `format: {type:"grammar", syntax:"lark"\|"regex"}`, "Model sampling is constrained using LLGuidance" ([docs](https://developers.openai.com/api/docs/guides/structured-outputs)) | First-party numeric limits (property count, nesting) **not verifiable** (section did not render); Azure mirror states "up to 100 object properties total, with up to five levels of nesting" (ms.date 2026-08-24) | GPT-5.6 family (2026-07-09) |
| Google | `response_format` with `application/json` + schema; `$ref` "for recursion"; `minimum`/`maximum`, `minItems`/`maxItems` supported; "Very large or deeply nested schemas may be rejected" ([docs](https://ai.google.dev/gemini-api/docs/structured-output), updated 2026-09-02) | Tools + structured output together is "Preview … Gemini 3 series models" only | — |

The Anthropic no-recursion rule is decisive for schema design: a nested `children: Node[]` tree schema is *unrepresentable*, while the flat `elements: Record<id, Node>` map with `children: string[]` is trivially representable. That is presumably why json-render and A2UI are flat — and it settles doc 03's "flat where possible" as "flat, full stop" on Claude.

**Does constraining hurt quality?** The 2025–2026 literature converged: *The Format Tax* (arXiv 2604.03616, Apr 2026) finds "format-requesting instructions alone cause most of the accuracy loss, before any decoder constraint is applied" and "newer closed-weight models demonstrate minimal to no format penalty"; *The Constraint Tax* (2605.26128, May 2026) shows sub-3B models going from 61.5%→100% validity while accuracy drops 19.7%→11.0%; *Thinking Before Constraining* (2601.07525) recovers "accuracy gains of up to 27%" by reasoning unconstrained first, then decoding constrained. Practical rule for the pipeline: adaptive thinking on, schema-constrained output last, and never run the selection step on a sub-7B local model without measuring.

**Constrained-decoding cost** is no longer a concern at API scale: llguidance reports "50μs of CPU time per token (for 128k tokenizer)"; vLLM defaults to `auto` across xgrammar/guidance/outlines ([vLLM docs](https://docs.vllm.ai/en/latest/features/structured_outputs.html), 2026-05-19); *Trie Automata* (2608.12574) claims "7X faster per-step valid-token computation … compared to XGrammar", relevant if the component-type enum grows into the hundreds. JSONSchemaBench (2501.10868) has no 2026 revision.

**Economics, recomputed** — 15k-token cached catalog + 1k dynamic input, 9k-token from-scratch TSX vs 1.5k-token construction file, prices from [platform.claude.com/docs/en/about-claude/pricing](https://platform.claude.com/docs/en/about-claude/pricing) (cache read 0.1× base; Sonnet 5's "$2/$10 … introductory pricing … is now the standard price") and the OpenAI/Gemini pricing pages (sub-track):

|---|---|---|---|---|
| Claude Sonnet 5 ($0.20 / $10) | $0.093 | $0.018 | 5.2× | $0.93 vs ≈$0.04 |
| Claude Haiku 4.5 ($0.10 / $5) | $0.047 | $0.009 | 5.2× | $0.47 vs ≈$0.02 |

Two things changed since doc 03 §5. First, the ratio holds (≈5×) but the absolute numbers collapsed to cents per screen, so **cost is no longer the argument**; latency (9k output tokens streamed vs 1.5k) and reliability are. Second, the DS-import comparator (2–4.5k tokens of TSX against a real design system) shrinks the ratio to ~2×, and Claude 4.7+'s tokenizer "produces approximately 30% more tokens for the same text" — it inflates both sides equally. Prompt caching now contributes only ~$0.027 per Sonnet 5 call; the "catalog is nearly free in context" claim is true but immaterial.

**Small models for selection:** BFCL V4 (page 2026-04-12) puts Claude Haiku 4.5 at 68.70% overall (Non-Live AST 86.50%) ahead of GPT-5-mini 55.46% and Gemini-2.5-Flash 56.24%; *GraphRAG on Consumer Hardware* (2605.20815) warns "models below approximately 7B parameters fail to reliably produce valid structured outputs". Haiku-class hosted models are a safe floor for E1's "small-model floor" experiment; local sub-7B is not.

## 5. Edit formats and patch reliability

The evidence base under doc 05 has shifted from *diff format* to *addressing scheme*.

- **aider's leaderboard is frozen** ("Last Updated: November 20, 2025"; data file last committed 2025-10-04; last release v0.86.0, 2025-08-09 — [leaderboards](https://aider.chat/docs/leaderboards/)). Every top-8 entry uses search/replace (`diff`/`diff-fenced`); GPT-5 (high) leads at 88.0% correct with the *lowest* format compliance in the top 8 (91.6%). The "20% vs 61%" unified-diff result is still on the site ([unified-diffs](https://aider.chat/docs/unified-diffs.html)) but is a GPT-4 Turbo laziness artifact from 2023-12; doc 05's use of it as evidence for "format choice matters" stands, its use as evidence for *udiff* does not.
- **Positional patches are the worst format; stable ids are the best.** Bölük's 16-model harness study (2026-02-12; 180 tasks × 3 runs) concludes "Patch is the worst format for nearly every model" and that tagging lines with 2–3-char content hashes as stable ids ("hashline") lifted Grok Code Fast 1 "6.7% → 68.3%", "+15 points average", with output tokens down "up to 61%" ([stencil.so](https://stencil.so/blog/the-harness-problem)). *Don't Let the Model Write the YAML* (arXiv 2609.00227, 2026-08-31) on Kubernetes manifests: unified diffs "under strict patching almost none apply"; GNU patch "applies 96%, yet silently misapplies about 1 in 7 (14–20%)"; its fix is to have the model emit field-change *intents* and let a deterministic YAML-aware writer apply them. *PatchBoard* (2605.29313, 2026-05-28) "replaces inter-agent dialogue with validated JSON Patch mutations over a shared structured state": "84.6% success rate, compared with 30.8% for LangGraph". *Diff-XYZ* (2510.12487): "search-replace format performs best for larger models."
- **JSON Whisperer** (2510.04717) still reports "reduces token usage by 31%" and "within 5% of full regeneration" — with **0 citations** in OpenAlex; **trustcall** is dormant (last push 2025-07-17, PyPI 0.0.39 from 2025-04-14). The pattern outlived its reference implementations: json-render's SpecStream is now the largest production use of LLM-emitted RFC 6902 ("each line is a JSON patch operation"), and AG-UI's `StateDelta` is RFC 6902 too.
- **Native edit tools.** Anthropic's text editor is still `text_editor_20250728` (`str_replace_based_edit_tool`; no 2026 version in the [tool reference](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-reference)); Claude Code's `Edit` enforces read-before-edit, exact match ("A single character of whitespace or indentation difference is enough to miss"), and uniqueness ([tools reference](https://code.claude.com/docs/en/tools-reference.md)). OpenAI's `apply_patch` became a native tool type with GPT-5.1 (2025-11-13; V4A diff, no line numbers): "the named function decreased apply_patch failure rates by 35%" ([GPT-5.1 guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5-1_prompting_guide)). OpenAI Predicted Outputs lists no GPT-5-family support.
- **Fast-apply** is a commodity at identical prices: Morph "10,500 tok/s", "98% accuracy", morph-v3-fast $0.80/$1.20 per MTok ([morphllm.com](https://morphllm.com/)); Relace `relace-apply-3` $0.80/$1.20, "over 3x faster and cheaper than rewriting files from scratch", frontier models "reach roughly 96% edit success" ([relace.ai](https://www.relace.ai/blog/relace-apply-3)). All accuracy numbers are vendor-reported; no independent merge benchmark exists.

Implication: doc 05's two rules — id-keyed children, RFC 6902 against a schema-validated document — are the *strongest*-supported part of the architecture in 2026, and the YAML paper's "intent, not patch" variant (the model names the field and value; the builder computes the edit) is worth adopting as the default edit verb.

## 6. Research and benchmarks

This track was stopped before completion; only the following are verified. JSONSchemaBench (2501.10868) has no 2026 revision. UIBenchKit (2605.13141, already cited in [eval-tuning-loops/01](../eval-tuning-loops/01-grading-generated-prototypes.md)) packages Design2Code-style metrics; none of those metrics measures on-system adherence. The only UI-as-data quality numbers found anywhere are thesys's vendor benchmark (§2) and A2UI's in-repo Genkit eval harness, which "publishes no results." **Not verified:** WebGen-Bench, DesignBench, ArtifactsBench, FullFront, Interaction2Code, DeclarUI, LayoutCoder, DCGen, any 2026 "design-system-aware generation" paper, and any paper comparing "emit DSL/JSON then render" against "emit code directly" — this comparison appears not to exist in the literature and is the gap E1/E3 would fill. Modular Layout Synthesis (2512.18996) and MermaidSeqBench (2511.14967) were not re-checked.

| Codegen over runtime interpretation (04) | **Still open, now differentiated** | Every shipping format is an interpreter; `@json-render/codegen` is a toolkit not a path; nobody produces committed, diffable TSX |
| File-granularity ownership, builder- vs LLM-owned files (05) | **Still open** — no external evidence either way | Claude Design's design-system validation and Figma's Code Connect discovery are catalog *retrieval*, not ownership splits |
| Plan/apply preview UX (06) | **Still open** — no product shows a spec diff before rebuild | json-render `validateSpec`/`autoFixSpec` classify fixes as "lossy or lossless" — the closest analogue |
| JSON Patch iteration, corrective-patch repair (05) | **Confirmed** | SpecStream RFC 6902 in production; PatchBoard 84.6%; YAML-intent paper; trustcall itself dormant |
| Figma as a deterministic realizer (03 §4.6) | **Refuted** | `use_figma` is imperative JS in ≤10-op chunks with screenshot validation; no data-rendering path |

## 8. What to reuse vs build

**Reuse.**
- **json-render as the interpreter path and the catalog format** — `defineCatalog` + Zod props + `catalog.prompt()` + SpecStream is the runtime half of doc 04's hybrid, already at 1.36M weekly downloads with edit modes (`patch`/`merge`/`diff`), `validateSpec`/`autoFixSpec`, and `@json-render/yaml` for the human-review surface doc 03 wanted. Its flat spec is the construction file minus the pattern layer.
- **A2UI's envelope only if cross-runtime delivery matters** (Gemini Enterprise, AG-UI, Flutter); its `catalogId` + custom-catalog rules are a good template for catalog versioning, which doc 09 flagged as the missing migration story.
- **Anthropic structured outputs / strict tools** as the emission mechanism (no repair loop needed for schema validity; keep the semantic lint).
- **RFC 6902 with id paths** as the edit wire format, shared with SpecStream and AG-UI `StateDelta`.
- **shadcn as the naming baseline** — still the vocabulary all three formats ship first (`@json-render/shadcn`, 36 components); registry-format specifics **not verified**.
- **Fast-apply (Morph/Relace)** only for the LLM-owned code islands, never for builder-owned files.

**Build (the differentiated remainder).**
- The **deterministic offline builder**: spec → templates/ts-morph → Prettier → committed TSX with a generation manifest. Unoccupied by any product; `@json-render/codegen` supplies traversal/serialization helpers to build it on.
- The **pattern layer** over an atomic catalog (screens/sections) and the E2 evidence for it.
- **Plan/apply** diffs and drift detection over generated files.
- The **designer-owned catalog extractor** (docgen/cva/Code Connect → Zod) — Figma's discovery order (Code Connect → existing screens → library search) is the right source ranking to copy.
- A **compact inference DSL** is now optional rather than rejected: pilot it in E3 with the JSON schema kept as the validation layer, as A2UI Express does.

## 9. Open questions

1. Does a pattern layer (screen/section refs) beat an atomic catalog on validity and quality? No shipping format has one; E2 is unprecedented.
2. What is the real token/validity trade of a compact DSL on frontier models? Vendor numbers (67%, 55–70%) come from small-model or self-run settings.
3. Is there any on-system-adherence benchmark (percent of output using sanctioned components/tokens)? None found; the repo's grading stack would have to define it.
4. How does Claude Design validate output "against these components" internally, and does it expose the representation? Undocumented.
5. Is the shadcn registry still the de-facto catalog interchange, or has json-render's catalog become one? Not verified.
6. Does the context-rot threshold for catalogs still hold on 1M-context models with cheap cache reads?

## 10. Recommended updates to the E0–E6 roadmap

- **E0** unchanged, but add a second baseline: *json-render runtime interpretation with the same catalog* — the architecture must beat both "agent writes code" and "off-the-shelf interpreter".
- **E1** — build the vertical slice *on* `@json-render/core` catalogs and SpecStream rather than a bespoke schema; the builder consumes a json-render spec and emits TSX. Emit via `output_config.format` (flat schema, no recursion); do not use forced `tool_choice`.
- **E2** unchanged and now the highest-information experiment (no prior art).
- **E3** — replace "JSON vs YAML vs terse DSL" with "JSON vs OpenUI-Lang-style statements vs A2UI-Express-style DSL, all compiled to the same JSON before validation"; measure on Sonnet 5 and Haiku 4.5, not small local models.
- **E4** unchanged.
- **E5** — add the "intent, not patch" edit verb (field + value, builder computes the RFC 6902 op) as a third arm; measure silent-misapply rate, which the YAML paper shows is the real failure mode.
- **E6** unchanged; add CustomBlock rendering through json-render's registry escape so the interpreter and builder share the hatch.
- **New E7 — catalog migration**: version the catalog with an A2UI-style `catalogId`; test that specs written against v1 either build or fail loudly against v2.

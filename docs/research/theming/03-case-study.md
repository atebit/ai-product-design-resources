# Case Study — A Production Theming Layer, End to End

**Series:** Theming & Mathematical Color Mutation — doc 4 of 4

## Scope

The concrete system the previous three documents were extracted from: a production design system for a dark-first, data-dense portfolio/analytics product. This doc records the actual token values, the engine's published constants, the verified preset results, and — just as importantly — how the whole thing is packaged for AI agents. Values are reproduced as shipped; treat them as a worked reference implementation of the architecture, not as a palette to copy.

Supporting families: sentiment surface tints (`primarySurface`/`warningSurface`/`destructiveSurface`, 6–12% alpha), glass (`glassBg`, `glassBorder`) with paired scrims (`scrimStrong`, `scrimSoft`), radius (`0.75rem` buttons/cards, `6px` inputs), type (Inter UI / mono for code and token values).

Light mode mirrors the shape exactly (same keys, flipped values — e.g. `bgCard #FFFFFF`, `textPrimary #0F172A`, `destructiveText #9B0F2E`), which is what makes mode switching a single object swap.

What the table demonstrates: chroma clamping holds perceived vividness in a tight band across wildly different hues (dark 7.0–8.2), and the L 52% light-mode seat makes **every** generated hue reverse to white-on-color at ≥5:1. The one sub-AA-looking number (house green light, 3.3) is the deliberate hand-tuned exemption — and 3.3 still clears AA-large, which is how the button label (bold, on `onPrimary` white) is spec'd.

## 4. The distribution model — theming as agent infrastructure

The system treats itself as something an agent *installs*, and the theming rules travel with it. This is the part most design systems miss:

- **`/llms.txt`** — a ~2KB agent entry point at the domain root: a version check (a `DS-VERSION` line that must match the live site's version badge, else the agent re-fetches the kit), pointers to everything, and a compressed rule summary ("No hardcoded hex — use semantic tokens. Default to dark mode. `destructive` for fills/strokes only… accent is non-interactive, one per view max.").
- **`/design-rules.md`** — the portable source of truth (~13KB): full token tables with dark+light values, 14 hard rules with rationale, the theming pattern for inside and outside the monorepo, and component-usage guidance. Self-contained by design — works pasted into any project.
- **`/INSTALL.md` + `/AGENTS.md` + install kit (zip)** — per-tool entry points: Replit gets an agent-skill folder, Claude Code gets `CLAUDE.md` + the rules file, Cursor/Windsurf get `AGENTS.md` + the rules file, chat assistants get a paste-in instruction.
- **Interrogation before installation.** The kit *requires* the agent to clarify three things before writing files: target environment, what's being built, and codebase state — with an explicit risk-tier protocol ("For large/legacy apps STOP and push back — never uproot existing structure, adopt incrementally," phased plan with human-gated reviews).
- **Downloadable token artifacts** in three formats: CSS custom properties, Tailwind v4 `@theme` block, and raw JSON (semantic + chart + raw palette) — all generated from one token package, never hand-edited.

The consequence for theming specifically: because the *rules* (tier partition, no-hex, fill/text splits, dark default) travel as ~13KB of markdown, any agent building on the system produces UI that the mutation engine can safely re-theme later. The install kit is what makes the math durable.

## 5. Observations

1. **The system documents its own rationale inline.** The live docs explain *why* light mode runs deeper, *why* chroma clamps instead of fixing — the arguments in [01](01-oklch-color-mutation.md) and [02](02-contrast-preservation-and-reversal.md) are quoted from the shipped docs. Rationale-as-spec is what lets an agent extend the system without violating its physics.
2. **Live proof over promises.** The preset table is computed by the shipping engine on page load; the theme picker reflows the docs site itself. The docs are an acceptance test.
3. **The hand-tuned/generated boundary is explicit.** The house green keeps its hand-tuned `#16A34A` and navy surfaces; everything generated goes through the engine. Both regimes are named, so nobody "fixes" the flagship by running it through the machine.
4. **Brand governance and color math live at the same altitude.** "The wordmark is always caps" and "destructive is fills-only" sit in the same rule list — the system treats contrast law as brand law, which is exactly the promotion that makes agents obey it.
